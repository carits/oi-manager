# 组织模型迁移任务（历史说明）

本文件记录 2026-08 期间旧校园档案迁移到组织成员关系与组织档案时采用的约束。该迁移已经完成，旧的 `migrate-organization-model` / `migrate-organization-history` 可执行入口已经退役，**不得按本文历史命令尝试执行**。当前运行时以 `OrganizationMembership`、组织档案以及 2026-09-19 的组织兼容残留退役迁移为准。

当时的受控迁移只允许在阻塞项为 0 后补齐以下可唯一映射的数据：

- 学校对应的组织
- 学校成员关系
- 组织内学生档案与教师档案
- 学生主教练的组织成员关系

它不会删除或修改旧表、旧字段、提交历史、比赛历史，也不会执行原生 SQL。

## 阻塞项

下列情况会阻止写入和后续 Prisma 删列迁移：

- 学生、教师或校园资源指向不存在的学校
- 同一账号在同一学校同时存在学生与教师旧档案
- 学生的主教练不属于同一学校
- 学校负责人不是本校教师
- 团队、比赛、题库、题单、管理员或负责人转移记录无法映射学校

只有报告的 `blockingIssueCount` 为 `0`，才允许进入下一步：为校园资源补 `organizationId`、切换运行时读写、最后删除旧字段和旧表。



## 当前状态

- 旧组织迁移脚本已从仓库退出，不再是当前操作入口。
- 2026-09-19 的 `20260919_zz_retire_organization_compat_residue` 已作为当前 Schema 演进事实源，运行时代码不得重新依赖 `User.schoolId`、旧 Teacher/Student 表或旧校园角色。
- 后续业务数据修复默认通过受权限与审计保护的 API；新的受控迁移必须单独登记适用范围、阻塞条件、对账与恢复策略。
