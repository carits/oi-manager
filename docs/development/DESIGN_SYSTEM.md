# 设计系统

## 2026-09-05 私信工作台

一对一私信使用标准 PageHeader、Tabs、Button、Menu、表单控件、Empty、FormDialog 和 ConfirmDialog。桌面端使用会话列表与消息区双栏，窄屏降级为列表/详情分步视图；纯文本消息保留换行并允许长内容断行，不得产生页面横向溢出。联系申请和举报使用统一 FormDialog；归档、清空、移除联系人和拉黑使用统一确认语义，不自行实现遮罩。加载历史时保留滚动位置，用户查看历史时新消息只显示提示，不能强制滚动到底部。

账号头像统一使用 `components/user/UserAvatar`：必须处理资源 URL、Unicode 首字符回退、图片加载失败回退、圆形裁切、可访问名称和 `24/32/40/48px` 四档尺寸。AppShell、管理身份单元格和私信工作台不得各自重写头像逻辑。私信最近会话、聊天头部、搜索结果、联系人、联系申请和黑名单使用 40px 头像；连续三分钟内的对方消息归为一组并只显示一个 32px 头像，头像与首个气泡顶部对齐，自己消息不显示头像。会话时间按“今天时分 / 昨天 / 本年日期 / 跨年日期”降噪，消息时间使用同一相对日期规则。

私信工作台桌面左栏为 328px，选中会话使用浅色背景和左侧 3px 主色指示，不使用整块强蓝底。消息区使用弱背景区分内容层，对方使用带边框的浅色气泡，自己使用主色气泡；少量消息贴近输入区，空状态居中且不得使用占据大面积的虚线卡片。举报不得作为每条消息的常驻文字，桌面悬停/聚焦、移动端直接显示 `⋯` 菜单，菜单向上展开并提供复制、举报。输入框默认约 58px、按内容增长且最大 140px。输入区允许纯文本和已发布的平台表情包，不展示尚未实现的附件或用户上传入口；表情选择必须使用统一 Popover，点击即发送，失败不关闭，动态资源在 `prefers-reduced-motion` 下使用静态 poster。表情消息最大显示 144px、无文字气泡背景，仍保留时间和举报操作。

## 2026-08-25 统一组件契约

本文件是当前界面视觉与交互的唯一规范。`globals.css` 和 `components/ui` 是实现来源；业务组件
不得复制通用控件或弹窗。2026-08-27 当前业务源码中的原生按钮、原生表单控件、原生表格、
自定义 Dialog、直接 Modal、任意 Modal 宽度、硬编码视觉值和静态内联样式均已降为 0。
仅动态尺寸、坐标、资源 URL 和 CSS 自定义变量允许使用受控 `style={computedStyle}`；遗留白名单各分类均为空。

新增统一组件包括 Input、Textarea、Select、Checkbox、RadioGroup、Switch、SearchField、Combobox、
IconButton、Popover、Menu、DataTable、TableToolbar、Section、FormDialog、ConfirmDialog 和
DetailDialog。迁移中的旧实现登记在 `scripts/ui-legacy-baseline.json`；`pnpm ui:state-check` 阻止任意
文件增加静态内联样式、静态样式对象引用、原生控件、自定义 Dialog、任意 Modal 宽度和硬编码视觉值。
门禁同时识别 `style={{ ... }}`、`style={formStyles.field}` 和 `style={cardStyle}`，不能通过把对象移到常量中绕过。
组件选择和调用约束见[UI 组件契约](UI_COMPONENTS.md)。

### 紧凑密度与页面顺序

- 普通页面固定为 PageHeader → Toolbar/筛选 → 内容 Section/DataTable → Pagination。
- 控件默认高 38px，紧凑控件 32px，表头 42px，数据行不低于 48px。
- 管理页强调扫描和比较，不嵌套装饰卡片；详情与代码工作台可使用 workbench 全宽布局。
- 颜色、间距、字号、圆角、阴影和层级只使用全局语义 Token；业务 CSS 不新增等价硬编码值。
- 业务 TSX 和 CSS Module 不得声明十六进制或 `rgb/rgba` 值；竞赛奖牌、热力图、代码区、遮罩与阴影
  同样必须使用 `globals.css` 中的已命名语义 Token，不在业务模块内重建局部色板。
- 筛选字段必须使用持续可见的字段标签，不得只用 placeholder 或空选项表达字段含义。基础表单控件默认
  `width: 100%`，因此多字段筛选必须放入显式响应式 Grid；不得把全宽控件直接放回可换行 Flex 工具栏。
- 空筛选项使用“全部结果”“全部语言”等业务语义，不使用脱离上下文的 `All`。筛选区在桌面保持紧凑对齐，
  `1180px / 760px / 520px` 以下依次降为三列、两列和单列，操作按钮始终作为同一网格的末项。
- 比赛、训练和作业内的评测记录沿用相同筛选契约：题目、用户名（仅管理员）、评测结果和语言均使用
  持续可见标签；桌面保持单行，`960px` 以下两列，`560px` 以下单列，且不得产生页面横向溢出。
- 可点击表格行必须提供 `focus-visible` 样式，并覆盖浏览器对 `tr` 的默认黑色 outline；不能通过直接移除
  焦点反馈解决视觉问题。
- 同一业务名词不代表同一页面权限。训练等角色差异明显的列表必须先由已认证校园身份解析
  `student | teacher | school_principal`，再渲染学生任务视图或管理视图；不能仅因 URL 含学校 ID 就显示
  创建、编排、批改等管理操作。学生空状态解释任务为何为空，管理者空状态提供创建动作。
- 普通训练列表使用“训练列表 / 我的训练”和“个”，不把内部 `TrainingSession` 直译成“训练场次”。
- 训练只有 Stage 驱动的一套领域模型。快速创建显示一个 Stage，模板创建显示多个 Stage；不得出现“普通训练 / 教练带练”产品模式。卡片可用“Stage 数 · 题目数 · 学生数 · 截止时间”解释结构，学校管理视图若存在可管理团队，必须提供校级/团队范围筛选。
  学生按进行中、即将开始、已完成浏览；管理者按进行中、草稿、即将开始、已结束浏览，并提供搜索及
  需要时的团队筛选。普通列表宽度不超过 1240px；只有实际编排工作台使用全宽布局。

- Stage 设置先使用课堂语言：“这一阶段做什么、谁参加、每组练哪些题、题目怎么开放、练多久、什么时候结束”。内部枚举、Subtask、ANY/ALL 和最短持续时间放入高级设置。
- 基础学员名单与 Stage 分组必须分开呈现；不允许用 Session 级分组暗示学员整堂课永久同组。

### Dialog 契约

- FormDialog 用于创建/编辑，ConfirmDialog 用于确认和危险操作，DetailDialog 用于长内容与代码。
- 尺寸只允许 sm 420、md 560、lg 720、xl 960、wide 1200；旧 `width` 属性仅在迁移期兼容。
- 表单弹窗内部滚动；详情弹窗使用 page 模式且只有最右侧一个滚动条。
- 底部固定“取消 → 主操作”；提交中禁用重复操作、ESC、遮罩关闭和关闭按钮。
- dirty 表单关闭前确认；嵌套弹窗只有顶层处理 Escape/Tab，关闭后恢复触发点焦点。
- 640px 以下 Dialog 全屏，关键操作保持可见；桌面完整验收 1440×900 与 1280×720。
- 组织申请、邀请和审核统一使用 FormDialog；不为该业务新增 Drawer。学校管理继续在同一页面使用 SegmentedControl 切换学生、教师、申请、邀请和资产。
- 提交详情等长代码 Dialog 使用 page 滚动：纵向滚动条只允许出现在浏览器最右侧的 Dialog 外层；代码区
  只在超长单行时横向滚动，不得再设置固定高度或内部纵向滚动。弹窗和独立详情页必须复用同一内容组件。
- 403/404 属于永久详情状态，展示明确原因和关闭/返回操作，不显示“重试”；网络、限流和 5xx 才提供
  局部重试。错误区域不得通过刷新整个浏览器页面恢复。
- 详细测试点使用标准 Button Disclosure，默认折叠但保留总体 Verdict/总分/首个失败点；按钮必须提供
  测试点数量、`aria-expanded` 和 `aria-controls`，支持鼠标、Enter 与 Space。展开内容不得增加内部纵向滚动。

## 2026-08-26 OI 数据工作台

- OI 数据管理采用三栏工作台：Subtask、Group、Testcase 池。三栏共享一个吸顶操作栏、revision、总分和结构化错误摘要。
- Subtask 与 Official Group 支持拖放和键盘上移/下移；Hack Gate 使用成功语义色但保持只读，不伪装成普通可编辑卡片。
- `1280×720` 下 Testcase 池下移为整行，手机下三栏降级为分步纵向区域；页面本身不得产生横向溢出。
- 文件上传、同名替换和删除使用统一按钮与 ConfirmDialog；工作台不再暴露可编辑 JSON textarea。
- 顶部“历史版本”使用统一 DetailDialog 展示只读 Revision 列表与当时 Judge 投影；查看历史不能切换当前版本，也不能修改活动固定版本。
- 离开含未保存草稿的工作台必须确认，revision 冲突保留本地草稿并提示刷新，不自动覆盖。

## 2026-09-07 评测程序模板工作台

- “评测资产与生成”的评测程序首页常驻展示 STD、Validator、Classifier、Generator 四类模板；已有活动程序时也不能隐藏模板入口。
- 模板卡只显示语言、协议、版本和 Fixture/Profile/Schema 摘要；完整源码、协议、Fixture、教学说明与 Generator 配置使用统一 `DetailDialog` 按需展示。
- 新增程序向导必须明确选择“使用模板”或“空白开始”，不得在切换类型或语言时静默覆盖源码。恢复模板或 Fixture 前存在修改时必须确认。
- 模板载入后持续显示“教学示例，必须按当前题目修改”；源码编辑器标题必须区分模板源码、Validator DSL 与空白程序。
- Classifier 同屏展示当前题目 Subtask ID、分值和依赖；未知 ID 使用错误状态明确阻断预检，不把问题延迟到 Judge 日志。
- Generator 模板是源码、Parameter Schema、Profile 和 Fixture Context 的完整包，界面不得只加载其中一部分。
- 详情 Dialog 代码区可独立横向滚动，但页面继续只有 Dialog 外层一个纵向滚动；720px 以下模板卡与空白入口降为单列。

## 2026-09-08 Candidate 与 Selector 工作台

- 普通贡献者只展示“等待分类、等待语料、评估中、技术有效、低价值、等待替换、已纳入 Rxx”等粗粒度结果，不展示 Kill Vector、Holdout、历史错误源码或内部权重。
- 题目管理者的 Candidate Pool 必须按 Subtask 同屏显示正式点 `x/10`、错误程序数、行为簇数及 `CLOSED/LIMITED/OPEN`；自动发布按钮在没有 OPEN Subtask 时禁用并说明原因。
- Selector 预览必须调用服务端真实 dry-run，展示每个命中 Subtask 的基线质量、候选质量、增益、门槛和拟替换点；不得用 Candidate 单项分数冒充集合选择结果。
- 紧急发布使用 `FormDialog` 收集 10～1000 字审计原因，并明确说明它不能绕过结构、保护期、Official Core 和 Revision CAS。
- 测试点永久保护同样使用标准 `FormDialog`，不得调用浏览器 prompt；历史成员替换默认折叠但必须可追溯。

## 2026-08-01 UX 审查结论

当前界面的问题不是单一配色或某个页面样式，而是信息架构、页面布局和组件约束没有形成
统一产品语言。代码审查快照如下：

- 2026-08-01 审计时，171 个 TSX 文件中有 117 个直接写内联样式；该数字仅为历史基线，
  2026-08-27 已完成业务层静态内联样式清零。
- 60 个文件直接使用原生 `<button>`，22 个文件直接使用原生 `<table>`。
- 只有 56 个 App 页面引入 `components/ui` 基础组件。
- 页面和业务组件中存在 146 处独立的全屏高度、宽度上限或 `2rem` 页面边距声明。
- 90 个页面中有 84 个是 Client Component，页面结构、数据和交互仍高度耦合。

这些数字不表示内联样式或 Client Component 本身必然错误，但当前规模已经造成可观察的
不一致：同类页面的标题、容器、Tab、筛选、按钮、卡片和空状态各自实现；`AppShell`
提供页面容器后，部分业务页面再次增加 `1200px` 宽度和 `2rem` 边距；hover 多通过
事件直接改样式，键盘焦点和等待反馈没有统一契约。

### 人的真实目标

页面首先服务角色正在完成的任务，而不是展示数据库里有哪些对象：

| 角色 | 进入系统后首先需要知道 |
|------|------------------------|
| 学生 | 现在要做什么、何时截止、上次提交结果、自己的进步 |
| 教师 | 哪些训练正在进行、谁需要处理、下一项管理动作是什么 |
| 学校负责人 | 学校运行是否正常、教师和学生是否存在待处理问题 |
| 平台管理员 | 用户、题目、提交和外部 OJ 是否有异常或积压 |
| 超级管理员 | 学校和平台管理员有哪些需要确认的变更 |

当前学生、教师和超管首页主要展示“快捷操作”和用户自己的用户名/角色，既重复顶部导航，
也没有回答上述问题。首页应改为工作摘要，而不是链接集合。

## 目标体验

- 用户进入页面后五秒内能判断当前位置、当前模式、最重要的数据和下一步动作。
- 页面标题、上下文、主要操作、筛选、内容和分页始终按同一顺序出现。
- 校园/个人模式的当前状态与切换动作分离表达，不能使用“校园模式 · 切换到个人”这种
  同时表达状态和命令的长按钮。
- 学生看到任务和进度，教师看到管理队列，管理员看到状态与异常；不同角色不共享空洞的
  “控制台”模板。
- 数据密集页面以扫描和比较为主，减少大卡片、装饰标签和无意义留白。
- 关键上下文和旧数据持续可见；等待、失败和刷新只占据对应内容区域。

## 信息架构目标

### 全局外壳

- `AppShell` 是页面边距、宽度和导航的唯一所有者，普通页面不得再次声明全屏容器。
- 左侧导航只允许两种形态：`>=1100px` 为 232px 完整侧栏，`<1100px` 为默认关闭的完整抽屉。
  不得增加只有图标的 compact rail，也不得通过裁剪 Logo 充当紧凑品牌标识。
- 桌面侧栏允许完全收起，并按账号与工作区记忆偏好；窄屏抽屉每次进入均默认关闭，临时开关不得污染桌面偏好。
- 抽屉必须具有遮罩、背景滚动锁定、`Escape`/遮罩/链接关闭、焦点限制和关闭后焦点恢复。
- 账号头像、姓名和账号用户名固定放在展开侧栏左下角；这里仅表达登录账号，不重复显示“学校”或当前
  工作区。当前学校与成员身份只由右上工作区切换器表达；点击账号卡后菜单向上展开，避免底部裁切。
- 工作区主界面身份使用“学生 / 教师 / 负责人”等自然称谓；“本校学生”等完整关系说明只在确需区分
  关系类型的管理表单中展示。
- Logo、导航、模式选择、通知和用户菜单使用稳定尺寸；任意导航状态只允许一个可见且可聚焦的 Logo。
- 模式选择使用“校园 / 个人”分段控件或菜单，明确当前作用域，并为切换提供进行中、失败
  回滚和缓存清理反馈。

### 页面骨架

普通列表和详情页统一为：

1. 页面标题、必要说明和一个主要操作。
2. 作用域、状态或时间筛选。
3. 数据列表、表格或详情正文。
4. 仅在确有必要时出现的批量操作和分页。

训练详情等高密度工作区可以使用全宽布局，但必须由 Shell 的明确 layout variant 提供，
不能在业务组件内部重新创建整页 Header、背景和最大宽度。

## 核心页面整改

### 首页

- 学生：首页使用统一学习任务视图聚合作业、训练和比赛，按“已逾期/进行中、24 小时内截止或开始、普通任务”排序；首页只展示前 N 条时，总数必须来自完整集合或服务端汇总，禁止使用 `slice()` 后的长度冒充总数。
- 教师：首页聚合作业、训练、比赛和成员待办并使用相同的紧急度排序；校园工作区中的团队、成员和提交统计必须固定到当前学校，不能混入账号在其他学校或个人空间的数据。
- 负责人身份只读取当前 `organizationRole` / Membership Context，不得再从全局账号 `role` 推断。团队分页列表必须分别返回全量团队数和全量成员关系数，卡片列表仍可只展示当前页。
- 管理员：首页优先展示异常、积压和最近变更，统计数字只作为辅助。
- 删除仅重复用户名、角色和顶部导航的“我的信息”“快捷操作”卡片。

### 团队

- 学生页面使用“我的团队”或“浏览团队”，不使用暗示拥有管理权限的“团队管理”。
- 校园团队按学校和成员关系扫描；个人团队按用户名和个人作用域展示，不泄露学校信息。
- 删除 Emoji 标签，使用统一图标和简洁文字；成员数、所有者、可见性保持固定位置。
- 创建团队使用明确主按钮和分步良好的表单，系统 ID 等技术字段提供就地解释。

### 作业、比赛和题单

- 作业和比赛按“进行中、即将开始、已结束”组织，并优先显示相对截止时间。
- 列表默认使用紧凑行或时间序列；卡片只在确实需要描述和封面时使用。
- 状态不能只依靠文字颜色，标题、截止、题数和完成进度形成稳定扫描列。

### 排名

- 固定展示当前用户的名次、Rating 和变化，并在表格中高亮当前用户。
- “Rating / 做题量”使用规范 Tab；“包含毕业学生”归入筛选区。
- 数据只有两页时不展示快速跳页等低价值控件；数字列使用 tabular numbers。
- 个人模式只显示用户名，校园模式显示姓名和年级，并明确排名作用域。

### 训练详情

- 合并重复的页面 Header，保留一个紧凑上下文栏。
- 公告较长时可展开，不能永久占据整条高亮色带。
- Tab 保持吸顶且保留各自状态；每个 Tab 只显示一个内容状态区域。
- 题目、评测、题解、附件和排名使用各自最合适的工具栏，不共用一套空白容器。

### 登录

- 登录角色使用规范分段控件，并以“学生登录”等明确标题确认当前入口。
- 表单错误贴近字段或提交区域，提交中保持按钮尺寸并防止重复操作。
- 开发账号提示仅在开发环境出现，不能成为页面的主要视觉内容。

## 组件整改顺序

1. 建立 `PageFrame`、`PageHeader`、`Toolbar`、`Tabs`、`SegmentedControl`、`DataTable`、
   `StatusBadge`、`EmptyState` 和稳定的表单字段组件。
2. 为按钮、链接、菜单、Modal 和表格行补齐 hover、focus-visible、disabled、pending 和
   键盘行为；Modal 增加语义、焦点进入和焦点恢复。
3. 引入项目统一图标库，替换 `+`、`×`、`▼` 和 Emoji；图标按钮必须有 tooltip 或
   可访问名称。
4. 页面样式从业务组件迁移到基础组件和有限的 layout variant，禁止继续复制页面容器。
5. 先改登录、各角色首页、团队、作业/比赛、排名和训练详情，再迁移低频管理页。

## 验收标准

- `1440×900` 和 `1280×720` 下，首屏能看到标题、当前作用域、主要操作和首批有效数据。
- 用户不依赖猜测即可区分当前模式、当前 Tab、可点击区域和操作结果。
- 学生能在五秒内找到最近截止任务；教师能在五秒内找到待处理事项。
- 同类页面不再拥有各自的宽度、边距、Tab、分页和空状态实现。
- 所有交互可通过键盘完成，焦点清晰，Modal 打开和关闭后焦点位置正确。
- 视觉回归覆盖登录、各角色首页、团队、作业、比赛、排名和训练详情；失败截图之外保留少量
  稳定基线。

## 原则

- 管理工具以扫描、比较和重复操作效率为主，不使用营销式大 Hero。
- 页面区域保持无框架布局；卡片只用于重复实体、弹窗和真正需要边界的工具。
- 不嵌套卡片，不使用装饰性渐变、光斑或大面积单一色主题。
- 文本、按钮和固定格式控件在两个桌面验收视口都不能溢出或重叠。

## 设计令牌

全局颜色、背景、文字、边框、圆角、阴影和间距定义在 `styles/globals.css`。组件优先
使用 CSS 变量，例如：

| 语义 | Token |
|------|-------|
| 主操作 | `--primary`, `--primary-hover`, `--primary-light` |
| 成功 | `--success`, `--success-light`, `--success-text` |
| 警告 | `--warning`, `--warning-light`, `--warning-text` |
| 错误 | `--error`, `--error-light`, `--error-text` |
| 页面/卡片 | `--bg-page`, `--bg-card`, `--bg-muted` |
| 文字 | `--text-primary`, `--text-secondary`, `--text-muted` |

业务组件不要新增可被现有 Token 表达的 hex 颜色。图表和具有明确语义的多色状态可以
保留专用调色板，但应集中定义。

## 控件

- 工具按钮优先使用已有图标库图标；保存、删除、编辑等熟悉操作不绘制自定义 SVG。
- 二元设置使用 toggle/checkbox，模式使用 segmented control，选项集合使用 select/menu。
- 卡片圆角不超过 8px，除非现有组件规范要求。
- 标题字号匹配容器；紧凑面板不使用 Hero 级字号。
- 按钮、棋盘、表格列和分页器使用稳定尺寸，hover 不改变布局。

## 状态与无障碍

- 错误、警告、成功不能只靠颜色表达。
- 可点击元素必须可键盘聚焦，并有可访问名称。
- Modal 管理焦点和关闭行为；表单错误关联对应字段。
- Axe `critical` 与 `serious` 问题阻断 UI CI，`moderate` 进入测试报告。除页面初始态外，Dialog、资源 Picker、Popover/Menu、Workspace Switcher 和移动端导航打开后也必须运行同一门禁。

## 评测程序工作流

- 评测程序编辑器不得以无说明的空白源码框作为入口；先展示中文职责，再提供协议摘要、推荐模板和样例。
- 协议、能力和模板必须读取共享 Registry，不允许在业务 JSX 中再维护另一套语言或模板常量。
- 使用渐进式披露：普通贡献者只看到“系统会自动校验/生成答案/分类”，管理员才展开 stdin、stdout、exit code、Schema 与资源限制。
- “上传源码”只读取到编辑器，不能立即持久化或激活；保存、预检、激活必须是三个可辨识的状态变化。
- 状态文案统一为“已编译、预检通过、已激活、已退役”，不能用单一“成功”掩盖生命周期阶段。

## 产品化工作流

- 高频复杂创建使用分步流程：作业固定为“基本信息 → 选择题目 → 选择学生 → 检查并发布”四步；比赛固定为“基本信息 → 赛制与 Rating → 题目 → 可见性 → 发布前检查”五步。比赛默认不计 Rating，选择计分范围后才展示权重和最低参赛人数；题目来源、题解开放和管理员排名集中在“可见性”，所有阻断项集中在“发布前检查”。
- 比赛选题的主入口必须是按校内、Carits 平台和其他题库分区的资源选择器，并显示已选 A/B/C 题目；OJ + 题号输入仅作为高级快速添加，不得成为默认工作流。
- 比赛和训练详情的一级标签统一为“题目 / 提交记录 / 题解 / 排名”。题目列表与题面合并为带左侧 A/B/C 导航的题目工作台，附件从具体题目的“题目资料”入口访问。
- 批量批改采用服务端分页的“学生 × 题目”矩阵，单元格显示主状态和次级标记，详细动作进入统一 `DetailDialog`。
- 所有参赛/作业/训练/Hack 源码提交使用 `SubmissionCodeEditor`；文件 IO 继续由独立字段组件承载。编辑器必须有纯文本降级，不能因动态依赖加载失败阻断提交。草稿键必须包含账号、业务范围、题目和语言；切换语言先保存旧语言草稿，再加载目标语言草稿，禁止复用当前文本覆盖目标语言。
- 内容作用域与导航作用域必须分离：知识文章仍由账号级发现 API 提供，但登录后的入口必须使用 `/personal/knowledge`、`/org/:organizationId/knowledge` 或管理端对应路由保留当前 AppShell；`/blog` 只承担公共分享。不得把所有入口压回一个会丢失身份外壳的根路由。
- 页面 Logo、侧栏、账号菜单、工作区切换和内容内固定引用必须共享同一个 `NavigationContext`。全局管理员优先使用平台上下文，不能因为进入 `/account/*` 被误判为个人工作区。
- 可编辑工作台统一向 `UnsavedChangesProvider` 登记 dirty scope。站内 Link、显式工作区切换和业务返回按钮必须触发同一确认框；刷新、关闭标签页继续使用 `beforeunload`。业务页面不得各自实现只覆盖其中一种导航的离开确认。
- 网络失败不得伪装为空数据。互动计数、评论、列表等只有在服务端成功返回明确空集合时才能显示“0/暂无”；失败必须显示局部错误、请求 ID（如有）和重试。

## Human UX Boundary

业务界面固定分为三层，不得将内部模型直接平铺给普通用户：

1. **普通层**：先显示“现在能做什么”、下一步和一个主操作。使用“测试数据版本”、“评测额度”、“质量证书”等人类文案。
2. **高级层**：通过明确的“高级设置”或“查看规则详情”展开，承载时间策略、计分权重、并发版本和资源范围。
3. **技术层**：只面向需要诊断的管理者，收纳 Revision ID、哈希、DQS/PQS 细分、Holdout、Feature、评测日志和协议数据。默认折叠，不得作为完成业务操作的必填输入。

统一规则：

- 页面首先显示结论、影响和可执行动作，再提供证据。
- 选择题目、学校、比赛、测试版本和质量证书时必须使用服务端资源选择器，普通层不接受内部 ID 手填。
- 题目、学生、团队和题单选择器必须使用服务端搜索与分页；跨页选择保存稳定 ID，切换关键词、筛选或页码不得丢失已选项。固定 `pageSize` 但不显示分页/总数属于静默截断，禁止用于业务选择器。
- 后端错误码经统一展示层翻译；ORM、SQL、堆栈、文件绝对路径和未解释英文状态不得进入 Toast 或普通错误页。
- 学生任务页不显示 Revision ID、内部哈希或评测管线术语；管理员可在技术详情中查看。
- 所有长表单、编排器、代码、Markdown 和测试图草稿均向全局 `UnsavedChangesProvider` 登记，不只依赖局部 `beforeunload`。
- 普通内容页的一级标签只保留高频阅读和操作；知识、附件、Hack、复制和归档等低频或管理动作进入语义明确的“更多”或“管理”菜单。
- 固定引用不能要求作者记忆题目、题解、榜单、Rating 或版本的内部 ID。题目和数据版本使用资源选择器；需要上下文的题解、榜单与 Rating 引用从对应来源页发起。
- “学校”是用户侧统一称谓；仅在架构文档、API 字段和确实跨组织类型的管理界面中使用“组织”。Evaluation Credits 在中文界面统一称为“评测额度”。
- 活动确需固定测试数据时，普通层只说明“数据已固定”“题库有更新”和更新影响；R 编号、哈希与并发版本留在技术详情。
