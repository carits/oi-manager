### 必须准确表达的限制

比赛仍是现有多个 API 请求，不是服务端整批事务。前端基线检查不能消除“检查之后、写入之前”的并发窗口，不能称为 A13/A14 完成。

只要比赛写请求已经发出后失败，或者检测到基线冲突，本轮过渡实现就停止当前表单的直接重试。用户仍能查看和导出本地草稿、打开新窗口核对服务器，但没有实现自动合并、自动重放或草稿 JSON 导入。它是在没有服务端幂等/事务保障前防止重复新增的保守措施，不是完整恢复体验。

题目历史来源中的未知字段、未知平台、非法 URL 类型、非法 JSON、空题号或超量数组都会进入不可安全读取状态。不会把历史异常视作“用户要求删除”。正常平台别名可以规范化；题号只 trim，URL 不改写。

公共查询仍仅按主平台和主题号检索；题目管理页原有的显式远程导入操作保持独立，没有把它加入检索兜底。

### 2. 完成 A01/A05/A07 的剩余边界

全仓定位创建、导入、账号、绑定、队列、缓存、提交与活动保存入口。复用共享规范化函数，不复制映射表；平台功能白名单与平台名称规范化分开。`vjudge` 等账号来源不能被误塞进题目来源集合。不要在未审计的历史大小写唯一键旁创建第二条规范记录。

### 3. 完成 A13/A14，再替换过渡恢复行为

为一个明确目标对象保存整个集合；先授权、校验所有条目、核对版本，再同一事务增加/删除/更新/排序。活动快照、数据槽/图版本、状态限制必须仍由已有领域规则控制。

先复用现有修订/幂等基础设施。每个相关写入口必须推进同一版本；同一请求标识不同规范内容必须冲突。没有可靠版本来源或需要新增持久化字段时，写清设计并进入后置数据库阶段，不能假装 updatedAt 已覆盖并发。

成功回执包含真实条目 ID、clientKey、最终顺序和版本；未知结果先核对或幂等重试，不用补偿删除伪装原子性。完成后移除本轮“写后失败一律停止直接重试”的过渡限制，保留准确错误反馈。

### 4. 完成 A08—A11 的六处选题闭环

目标为题单章节、比赛、作业、快速训练、训练设计器、运行期追加。逐行稳定 clientKey 与请求版本，按目标范围查重；改平台/题号立刻清空旧内部引用。找到、能选入、已选入、已保存是不同状态；缺 Stable 不等于没找到。

### 5. 完成 A15/A16 与交付记录

实现只读离线审计，不导出密码、Cookie、密钥、源码等敏感值，不在服务启动时自动执行。补仓库定向测试，再在批准的隔离环境做事务/并发测试。必要的架构库存通过生成脚本更新，不手改计数。
